# Deep Plan: Fix war-of-dots rendering defects, camera UX, and idle websocket traffic

## Problem Statement
Five user-reported defects in the war-of-dots server + WebGPU frontend:
1. Right-click drag pan is janky/stuttery and sometimes "loses focus of the mouse"
2. Quads have one missing triangle (one half is just black)
3. Cities are not visible
4. Default view should be more zoomed out
5. Rendering is slow; lots of websocket traffic even when idle

## Context

- **Repo layout**: Rust server in `src/` (axum + tokio + hecs ECS, CBOR protocol in `src/server/protocol.rs`), TypeScript WebGPU frontend in `frontend/src/` bundled by esbuild. `frontend/dist` is **baked into the binary at compile time** via `include_dir!("$CARGO_MANIFEST_DIR/frontend/dist")` (`src/server/game_server.rs:41`, `src/frontend/mod.rs:6`) — every frontend change requires `make frontend-build` **before** `cargo build/run`.
- **Render pipeline** (`frontend/src/game/renderer.ts`, ~1500 lines): 5 `createRenderPipeline` calls (lines 352, 422, 504, 583, 706) — **none sets `primitives.topology`**, so all default to `triangle-list`. Every vertex builder (terrain cells in `terrain.ts:120,131`, unit dots `renderer.ts:1016+`, symbol quads `~1033`, bars `~1076`, border quads `~1225+`, path segments `~1310`, city dots `~1348`, halos `~1385`, fog quad `updateFogQuad()` `~307-310`) pushes exactly **4 vertices in strip order TL,TR,BR,BL** → only triangle (v0,v1,v2) renders; the missing half shows the dark clear color (0.05, 0.05, 0.1). This single root cause explains issue 2 and makes city dots (12 world units) half-black/invisible (issue 3) and fog cover only the bottom-left half.
- **Bonus GPU waste**: `renderer.ts:864` — `renderPass.draw(this.unitVertexCount * 4)` where `unitVertexCount` already equals the vertex count (4 per unit); correct is `draw(this.unitVertexCount)`. Currently draws 4× more vertices than the buffer holds.
- **Camera pan** (`frontend/src/ui/controls.ts`): pointermove applies camera delta synchronously per event, calls `getBoundingClientRect()` on every event, and relies on one-shot `setPointerCapture` (line ~128) with no re-capture if the capture is implicitly released by the browser. Pointer handlers starve because the main thread is saturated by the render loop (no dirty check) plus 60 CBOR decodes/s (no server-side idle skip).
- **Camera init**: default `camera = { x: 0, y: 0, zoom: 1.0 }` (`renderer.ts:53`, mirrored in `game_state.ts:17`). `centerCameraOnTerrain()` (`frontend/src/net/connection.ts:322`) sets x/y to map center only — never zoom. Default map is 200×200 × `CELL_SIZE` 32 = 6400 world units; at zoom 1.0 a 1920-px canvas shows ~1920 world units, so all 5 cities (55–90 cells away) are off-screen. `ZOOM_MIN = 0.5` (`frontend/src/game/config.ts:26`) is higher than what's needed to fit the full map (≈0.27).
- **Server tick** (`src/server/game_server.rs`): `game_speed = 60` (config.toml) → 16 ms interval (line 203, interval loop line 447). Every tick, for **every** player: `build_delta_inner` (`src/server/delta.rs`) re-snapshots `game.unit_states()` and `game.query_cities()`, and **always** returns `ServerMessage::DeltaState` — even with every vec empty — which is CBOR-encoded and sent. `ECONOMY_TICK_INTERVAL = 1` (`src/game/constants.rs:7`, single consumer at `game.rs:794-797`) means funds for any city owner change every tick → delta never fully empty in a live game. `game_server.rs:529` clones all unit states per tick just for a count. The `prev_*` snapshots are **shared per-game** (declared once at `game_server.rs:213-228`, moved into the loop at 438-440) — not per-player.
- **Renderer hot path**: `startRenderLoop()` (`renderer.ts:765`) runs `updateCallback` + `renderFrame()` **every rAF unconditionally** — rebuilding all `number[]` vertex arrays, `new Float32Array`, `writeBuffer` (incl. re-uploading cached terrain mesh), 9 draw calls, fresh uniform array, and fresh bind groups (`createSymbolBindGroup()` `~863`, `createFogBindGroup()` `~881`, each also doing `texture.createView()`) — all of which depend only on static textures/samplers.
- **Replay player**: `ReplayPlayer` (`frontend/src/replay/replay_player.ts`) creates its own `Renderer` instance (line 58) and calls `startRenderLoop()` (line 63), so the dirty gate will apply to replay too — but `ReplayPlayer.applyEvent()` (line 80) mutates `gameState` without calling `markDataDirty()`, which would freeze replay at the first frame.
- Existing dirty tracking: `fogDirty`/`borderDirty` flags, `terrainMeshKey` CPU mesh cache (but still re-uploads every frame), `symbolCacheKey` atlas cache.
- `game_state.test.ts:42` asserts default camera `{0,0,1.0}` — plan keeps that default untouched (fix is in `centerCamera*`), so the test stays valid.

## Steps

### Phase A — Server (Issue 5a: WS traffic)

- [ ] **A1. `src/server/delta.rs` — change `build_delta_inner` signature and add early return**
  - Remove `game: &Game` parameter.
  - New signature:
    ```rust
    #[allow(clippy::too_many_arguments)]
    pub(crate) fn build_delta_inner(
        prev_units: &mut HashMap<String, UnitState>,
        prev_cities: &mut HashMap<String, CityState>,
        prev_funds: &mut HashMap<String, u32>,
        prev_vision_grid: &mut Option<Vec<Vec<bool>>>,
        prev_border_grid: &mut Option<Vec<Vec<u32>>>,
        current_units: &[UnitState],
        current_cities: &[CityState],
        all_player_funds: &HashMap<String, u32>,
        current_vision_grid: Option<Vec<Vec<bool>>>,
        current_border_grid: Option<Vec<Vec<u32>>>,
        player_id: &str,
    ) -> Option<ServerMessage>
    ```
  - Remove the internal `let current_units = game.unit_states();` and `let current_cities = game.query_cities()...` calls — use the passed-in slices instead.
  - Replace `game.player_funds(player_id)` with `all_player_funds.get(player_id).copied().unwrap_or(0)`.
  - After computing all delta fields, **before** the `*prev_* = ...` assignments, insert:
    ```rust
    let funds_changed = prev_funds.get(player_id).copied() != Some(player_state.funds);
    let prev_owned: u32 = prev_units.values()
        .filter(|u| u.owner == player_id)
        .count() as u32;
    if units_added.is_empty() && units_removed.is_empty() && unit_updates.is_empty()
        && city_updates.is_empty() && vision_grid_diff.is_none() && border_grid_diff.is_none()
        && !funds_changed && prev_owned == player_state.units_owned
    {
        return None;
    }
    ```
  - **On `None` return, the `*prev_* = ...` assignments are skipped** (snapshots are only updated when a delta is actually sent, so the next tick computes the diff against the last-sent state).
  - Update the stale comment at ~line 60 ("the map is tiny (20x20 ~ 1 KB)") to reflect the 200×200 default map.
  - **Unit tests** (`#[cfg(test)]` module in `delta.rs`):
    - Identical snapshots → `None` (and prev state unchanged).
    - Single unit position change → `Some(DeltaState)` with 1 `unit_updates` entry.
    - Funds-only change for player A → `Some` for A, `None` for another player with no changes.
    - City owner change → `Some` with `city_updates`.
    - Grid change → grid diff present in `Some`.
    - First tick from empty prev (units_added path) → `Some`.

- [ ] **A2. `src/server/game_server.rs` — tick loop: hoist snapshots + adapt send**
  - After `game.tick_game()` and the debug-stats block, hoist once per tick:
    ```rust
    let current_units = game.unit_states();
    let current_cities: Vec<CityState> = game.query_cities().iter().map(|c| c.into()).collect();
    let all_funds = game.all_player_funds();
    ```
  - In the per-player loop, call `build_delta_inner(...)` with the hoisted slices; wrap the send:
    ```rust
    if let Some(delta) = build_delta_inner(
        &mut prev_units, &mut prev_cities, &mut prev_funds,
        &mut prev_vision_grid, &mut prev_border_grid,
        &current_units, &current_cities, &all_funds,
        current_vision_grid.clone(), current_border_grid.clone(),
        &player.id,
    ) {
        let encoded = encode_message(&delta);
        if player.tx().send(encoded).await.is_ok() {
            alive.push(player);
        }
    } else {
        alive.push(player);
    }
    ```
  - **Note**: `prev_*` snapshots are **shared per-game** (declared once at `game_server.rs:213-228`, moved into the loop at 438-440), not per-player. The funds check is per-player via `prev_funds.get(player_id)`, so cross-player funds changes won't cause extra sends. The vision/border grid being shared across players with different vision is a **pre-existing design** — do not change it here.
  - Update `prev_funds` once after the per-player loop: `*prev_funds = all_funds;` (only when at least one player got a delta, or unconditionally to keep the snapshot fresh — pick one and be consistent).

- [ ] **A3. `src/server/game_server.rs:529` — cheap debug count**
  - Replace `gs.entity_count = game.unit_states().len() + game.query_cities().len();` with `gs.entity_count = game.unit_count() + game.query_cities().len();`
  - Remove `#[allow(dead_code)]` at `src/game/game.rs:652`.
  - Rewrite the active-player check (lines 543-545) to iterate the hoisted `current_units`/`current_cities` instead of re-calling `unit_states()`/`query_cities()`.

- [ ] **A4. `src/server/game_server.rs` — replay loop (~1228-1240)**
  - Adapt to the new `build_delta_inner` signature (pass pre-computed slices per event).
  - `if let Some(delta) = ... { send }` pattern.

- [ ] **A5. `src/game/constants.rs:7`**: `ECONOMY_TICK_INTERVAL: 1 → 10`
  - Only consumer is `game.rs:794-797` (economy tick gate). No other consumers found.
  - Gameplay effect: income accrues in 10-tick batches (~1.6 s) instead of per-tick (~16 ms). Totals are identical; the counter updates 10× less often. This is the **only behavior-affecting change** in this plan and is trivially revertible.

      const { width, height } = this.canvas;
      if (width === 0 || height === 0) return; // canvas not sized yet

    private panFrameId: number | null = null;

  - New helper:
    ```ts
    private refreshRect(): DOMRect {
      this.canvasRect = this.canvas.getBoundingClientRect();
      return this.canvasRect;
    }
    ```
  - **pointerdown** button 2 (~line 122-129): keep `preventDefault()`; set `isDragging = true`, `rightDragStart = {x, y}`, `lastPointer = {x, y}`; call `this.refreshRect()`; wrap `setPointerCapture` in `try/catch`; call `this.startPanLoop()`.
  - **pointermove** while dragging (~line 132-146): store `this.lastPointer = {x: e.clientX, y: e.clientY}`; re-capture if lost: `if (!this.canvas.hasPointerCapture(e.pointerId)) { try { this.canvas.setPointerCapture(e.pointerId); } catch {} }`. **No camera mutation here** — the pan loop handles that.
  - New **`startPanLoop()`**:
    ```ts
    private startPanLoop(): void {
      if (this.panFrameId !== null) return;
      const step = () => {
        if (this.isDragging && this.lastPointer) {
          const rect = this.canvasRect ?? this.refreshRect();
          const dx = this.lastPointer.x - this.rightDragStart.x;
          const dy = this.lastPointer.y - this.rightDragStart.y;
          const scaleX = this.canvas.width / rect.width;
          const scaleY = this.canvas.height / rect.height;
          this.camera.x -= dx * scaleX / this.camera.zoom;
          this.camera.y -= dy * scaleY / this.camera.zoom;
          this.rightDragStart = { x: this.lastPointer.x, y: this.lastPointer.y };
        }
        this.panFrameId = requestAnimationFrame(step);
      };
      this.panFrameId = requestAnimationFrame(step);
    }
    ```
    - This matches the **existing** delta formula (`canvas.width / rect.width` ÷ `zoom`) exactly, just applied once per rAF instead of once per pointermove event.
    - `rightDragStart` is reset to `lastPointer` each frame, so the delta is always incremental — no drift.
  - New **`endPan()`**: cancel `panFrameId` (via `cancelAnimationFrame`), set `isDragging = false`, `lastPointer = null`, release capture if held. Call from pointerup button 2 (~line 152) and pointercancel (~line 173).
  - **Resize listener**: add `window.addEventListener('resize', () => this.refreshRect())` in `setupEventListeners` (~line 90).
  - **`mouseToGameCoords` / `hitTestUnit` / `hitTestCity`**: replace `getBoundingClientRect()` with `this.canvasRect ?? this.refreshRect()`.
  - Note: a `dispose()` method for the resize listener is **not** added (page-lifetime app, not worth the churn).

## Ordering & Dependencies

1. **Phase A (server)** is independent of Phase B; can be a separate commit.
2. **B1 (topology)** must come **before** any visual verification of B4 (zoom) and city visibility — everything renders as half-quads until the topology fix.
3. **B4 (zoom)** before **B5 (dirty gate)** — the gate makes visual debugging harder if the camera logic is wrong.
4. **B7 (replay markDataDirty)** must accompany **B5** — the dirty gate freezes replay without it.
5. `make frontend-build` before `cargo run` for any frontend change.

## Verification

1. **Build & run**: `make frontend-build` then `cargo build && cargo run -- --config config.toml` (port 8080). Debug-stats variant: `cargo run --features debug-overlay`.
2. **Issue 2 (missing triangles)**: Start game → all terrain quads, unit symbols, health/org/equip bars, border segments, path preview, city dots, own-side halos, and fog render as **full quads** (no black half). Fog covers the entire screen, not just the bottom-left half.
3. **Issue 3 (cities invisible)**: On join, all 5 cities (4 corners + (100,45)) are visible as full colored dots with DOM level labels.
4. **Issue 4 (default zoom)**: On join (spectator or fresh player), the view is zoomed out to ~map-fit (≈0.3 zoom on 1920×1080 for the default 6400×6400 world). Wheel zoom can go down to 0.3.
5. **Issue 1 (pan jank/focus)**: Right-drag pan is smooth at display refresh rate. Dragging past the window edge / releasing outside keeps 1:1 tracking until release. No jank even with 60 Hz ticks running.
6. **Issue 5a (WS traffic)**: Two connected clients, no commands → server sends **zero** DeltaState messages while idle. Verify in browser DevTools (WS frames) or `console.debug('[WS] ←')` logs on localhost.
7. **Issue 5b (render perf)**: With a static camera and no game changes, the renderer performs ~0 GPU work between server deltas. Verify via browser Performance monitor: draw calls / frame times drop to near zero when idle.
8. **ECONOMY_TICK_INTERVAL=10**: Funds counter for a city owner updates ~10× less frequently. Income totals unchanged over time.
9. **Replay mode**: `/ws/replay?game_id=…` still streams events and ends correctly with a final FullState. Local JSONL replay (ReplayPlayer) does not freeze.
10. **Regression gate**: `make test` (cargo + vitest) and `make frontend-check` (fmt/lint/typecheck) clean.
11. **Manual/edge cases**: Test with a small custom map file through `load_map` for the zoom-fit math. Drag right-button while pointer exits the window. Rapid browser-tab/pointer-cancellation. Zoom wheel at the new 0.3 floor.

## Out of Scope / Follow-ups
