# Deep Plan: Criterion Microbenchmarks Integration

## 1. Context & Motivation

The War of Dots integration benchmark (`src/benchmark.rs`) measures full game tick throughput over ~1500 ticks with AI battle simulation. It tells you *which* system slowed down, but not *why*. This plan adds 35 Criterion microbenchmarks targeting specific operations (SpatialHash, ECS ops, each game system at scale) with statistical rigor, complementing the integration benchmark.

### Goals
- **Fine-grained visibility**: Pinpoint regressions at the operation level (e.g., "SpatialHash insert 1000 is 15% slower")
- **Statistical rigor**: Criterion provides mean, std_dev, confidence intervals — not just wall-clock averages
- **CI-friendly**: ~60s total run time with reduced sample sizes
- **Seamless integration**: Same `--benchmark` CLI, new results appear in the HTML report automatically
- **Optional**: Gated behind `--features microbenchmarks`, no impact on default builds

## 3. Criterion Integration Strategy

### Feature Flag
```toml
[features]
microbenchmarks = ["dep:criterion"]

[dependencies]
criterion = { version = "0.5", optional = true, default-features = false, features = ["plotters"] }
```
**Rationale:** Regular optional dep (not dev-dep) because it runs from the main binary. `default-features = false` strips unnecessary output features.

### Programmatic API
Criterion is invoked programmatically (not via `cargo bench`):

```rust
fn bench_one(c: &mut Criterion, group: &str, id: &str,
             f: impl FnMut(&mut Bencher<'_>)) -> MicrobenchmarkResult {
    let mut g = c.benchmark_group(group);
    g.bench_function(id, f);
    let s = g.finish();
    MicrobenchmarkResult {
        id: format!("{}/{}", group, id), group: group.to_string(),
        mean_ns: s.mean().0.as_nanos() as f64,
        std_dev_ns: s.std_dev().map(|sd| sd.0.as_nanos() as f64).unwrap_or(0.0),
        median_ns: s.median().map(|m| m.0.as_nanos() as f64).unwrap_or(0.0),
        n: s.iterations() as u32,
    }
}

let criterion = Criterion::default()
    .sample_size(10).warm_up_time(Duration::from_secs(1))
    .measurement_time(Duration::from_secs(2)).without_plots();
```

### Configuration Tuning
- `sample_size(10)`: 10 samples (vs default 100) — fast CI-friendly runs
- `warm_up_time(1s)`: Warmup caches before measurement
- `measurement_time(2s)`: Each benchmark measures for ~2 seconds
- `without_plots()`: No file output needed — we collect results programmatically

### `src/microbenchmarks.rs` (NEW, ~600 lines)
Structure:
```rust
//! Criterion microbenchmarks for War of Dots ECS game systems.
//! 
//! Gated behind `--features microbenchmarks`. Run programmatically via
//! `run_microbenchmarks()` which returns `Vec<MicrobenchmarkResult>`.

use criterion::{Criterion, Bencher, BatchSize};
use std::time::Duration;

/// Single microbenchmark result
#[derive(Debug, Clone)]
pub struct MicrobenchmarkResult {
    pub id: String,
    pub group: String,
    pub mean_ns: f64,
    pub std_dev_ns: f64,
    pub median_ns: f64,
    pub n: u32, // iterations
}

/// Create a Criterion instance tuned for CI-friendly runs.
fn make_criterion() -> Criterion {
    Criterion::default()
        .sample_size(10)
        .warm_up_time(Duration::from_secs(1))
        .measurement_time(Duration::from_secs(2))
        .without_plots()
}

/// Run a single benchmark and return its result.
fn bench_one(c: &mut Criterion, group: &str, id: &str,
             f: impl FnMut(&mut Bencher<'_>)) -> MicrobenchmarkResult {
    let mut g = c.benchmark_group(group);
    g.bench_function(id, f);
    let s = g.finish();
    MicrobenchmarkResult {
        id: format!("{}/{}", group, id),
        group: group.to_string(),
        mean_ns: s.mean().0.as_nanos() as f64,
        std_dev_ns: s.std_dev().map(|sd| sd.0.as_nanos() as f64).unwrap_or(0.0),
        median_ns: s.median().map(|m| m.0.as_nanos() as f64).unwrap_or(0.0),
        n: s.iterations() as u32,
    }
}

// ---- Benchmark Groups ----

fn bench_spatial_hash(c: &mut Criterion) -> Vec<MicrobenchmarkResult> { /* 8 benches */ }
fn bench_ecs_ops(c: &mut Criterion) -> Vec<MicrobenchmarkResult> { /* 7 benches */ }
fn bench_systems(c: &mut Criterion) -> Vec<MicrobenchmarkResult> { /* 14 benches */ }
fn bench_map_settings(c: &mut Criterion) -> Vec<MicrobenchmarkResult> { /* 6 benches */ }

// ---- Public Runner ----

/// Run all microbenchmarks and return results.
pub fn run_microbenchmarks() -> Vec<MicrobenchmarkResult> {
    let mut c = make_criterion();
    let mut results = Vec::new();
    
    println!("🔬 Running microbenchmarks...");
    results.extend(bench_spatial_hash(&mut c));
    results.extend(bench_ecs_ops(&mut c));
    results.extend(bench_systems(&mut c));
    results.extend(bench_map_settings(&mut c));
    
    // Print summary
    for r in &results {
        println!("  {:<40} {:>12.1}ns ± {:.0}ns ({} iters)", 
                 r.id, r.mean_ns, r.std_dev_ns, r.n);
    }
    results
}

/// Convert results to JSON for integration into the HTML report.
pub fn results_to_json(results: &[MicrobenchmarkResult]) -> serde_json::Value {
    serde_json::json!({
        "benchmarks": results.iter().map(|r| serde_json::json!({
            "id": r.id, "group": r.group,
            "mean_ns": r.mean_ns, "std_dev_ns": r.std_dev_ns,
            "median_ns": r.median_ns, "n": r.n,
        })).collect::<Vec<_>>()
    })
}
```

- Columns: Group, Benchmark, Mean (µs), Std Dev (µs), Iterations, Delta (prev)
- Green/red deltas for previous-run comparison (same pattern as system timings)

## 9. Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Criterion compilation time increases | Medium | Optional feature — only compiled with `--features microbenchmarks` |
| Some benchmarks are too slow (e.g., full_tick_500) | Low | Reduced sample_size(10) keeps each benchmark to ~2s |
| SpatialHash benchmarks don't reflect real usage | Low | Buffer reuse and dense cluster variants cover real patterns |
| HTML report too large with microbenchmarks | Low | Table is compact; ~35 rows add ~20KB to HTML |
| Previous comparison breaks if benchmark id changes | Low | IDs are stable strings; comparison is graceful on missing data |
