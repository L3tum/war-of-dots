## Goals / Non-goals

**Goals**
1. Eliminate the per-tick deep-clone of the unit/city snapshot (O1) and the 40 KB grid copies (O3), cutting network-phase allocs/bytes.
2. Shrink the wire: omit absent `Option` fields (O2); quantize supply digests to kill per-tick update churn (O6).
3. Stop recomputing the shared delta phase for spectators (O4) and stop cloning the full encoded message per send (O5).
4. Micro-hygiene: per-owner count maps (O7), small cleanups (O9).
5. Every item lands as its own commit with A/B or unit-test verification, plus `cargo fmt` + `cargo clippy` clean.

**Non-goals**
- No protocol *shape* changes (O10 sparse grids — separate branch), no parallelism re-attempts (rayon removal is final), no f32 wire-width changes (already minimal), no game-logic/ECS changes, no frontend logic changes (W2/W3 leave the wire shape and JSON schema unchanged; type regeneration is a no-op drift guard).

### W9 = O8 — (Optional stretch) Encode shared delta segment once, splice per player

**Do only after W2/W3/W4/W5 have landed** and only if the A/B leaves `net_ms` meaningfully hot.

**What/why.** Each player's `GameDeltaMessage` differs only in `player: PlayerState`, `vision_grid_diff`, and `grid_width`, yet ciborium re-serializes the shared segments (`border_grid_diff`, `units_added`, `units_removed`, `unit_updates`, `city_updates`) P times. At 240 units / P=4, estimated 20–40% of non-grid encode time.

**Files to modify.** `src/server/delta.rs` (`SharedDeltas` + `shared_encoded: Vec<u8>` + pre-encoded key constants), `src/server/protocol.rs` (new `encode_delta_spliced` helper), `game_server.rs` / `benchmark.rs` (call switch).

**Design (byte layout — must match serde field order exactly).** `GameDeltaMessage` serializes as a CBOR map in declaration order (`protocol.rs:18-36`): `player`, `vision_grid_diff`, `border_grid_diff`, `grid_width` (skip-if-none), `units_added`, `units_removed`, `unit_updates`, `city_updates`. `skip_serializing_if` makes the entry count **dynamic (6–8 depending on which Options are present)**. Correct per-player splice layout:

```
[map header, count = 6–8]
[vision_grid_diff]  (key + value, if present)
border_grid_diff    (SHARED — spliced bytes, first shared field)
[grid_width]        (key + value, if present)
units_added         (SHARED)
units_removed       (SHARED)
unit_updates        (SHARED)
city_updates        (SHARED)
player              (per-player, LAST)
```

Implementation: in `compute_shared_deltas`, encode the 5 shared key/value pairs **once** into `Vec<u8>` (a private struct holding exactly those fields, encoded without a map header, keys in the order above), with key strings pre-encoded as `&'static [u8]` constants. Per player: emit the map header (dynamic count matching the full message), then the per-player leading fields in order, then append the shared bytes, then the `player` entry. Reuse `estimate_delta_size` for capacity. Float int-coercion (`protocol.rs:254-258`) is inherited automatically since the splice reuses already-encoded bytes — but map-header and per-field framing must be verified byte-for-byte.

Keep `encode_message` as the fallback path (runtime toggle, default off) for debugging; **rollback is a single flag flip**.

**Risk.** Moderate: hand-laid CBOR must match ciborium's output exactly.

**Verification (required).** Byte-for-byte test: fixed seeded `GameDeltaMessage` (populated shared segments + 2 players, including one with `vision_grid_diff: None` to exercise the dynamic count) → assert spliced bytes **equal `encode_message(&msg)` byte-for-byte**, and `ciborium::from_reader` decode equality. A/B: `net_ms` down ~(P−1)/P of shared-segment encode cost.

## Rollback / Compatibility

W1/W4/W5/W6/W7/W8 are server-internal.
- **Behavior deltas (deliberate, flagged):**
  (a) **Spectators receive per-tick shared unit/city updates on any shared-dirty tick** (W1, finalized by W5) — previously the post-commit recompute at `game_server.rs:660-704` made the spectator's shared segments effectively always empty; frontend `applyDelta` handles them.
