# Deep Plan — Fix Frontend: Lobby UI, Settings Label, Game Rendering

## Context

User report (verbatim): *"The frontend is pretty broken. The lobby creation doesn't remove the lobby creation UI, the settings still say to enable the City Upgrade & Supply system (Supply is always active!), the game rendering itself doesn't work at all either."*

Two of the three symptoms (lobby UI unresponsive + blank canvas) share a **single root cause**: the Rust static-file handler `serve_static` (`src/server/game_server.rs:907-917`) is typed `Result<axum::response::Html<String>>` and returns `Html(content)` for **every** file in the baked `FRONTEND` dir (`include_dir!("$CARGO_MANIFEST_DIR/frontend/dist")`, line 41). `Html` forces `Content-Type: text/html`, so `/main.js` (referenced by `<script src="main.js">` at `frontend/index.html:612`) is blocked by every modern browser's MIME-type checking. Result: **no frontend JS executes at all** — no event listeners, no WebSocket, no WebGPU context, no render loop. The lobby form is inert HTML and the canvas stays blank.

The third symptom is a mislabelled settings checkbox that conflates two independent features.

## Approach

### Fix 1 + 3a — Correct MIME types in `serve_static`

Rewrite `serve_static` in `src/server/game_server.rs` to return `Result<Response, StatusCode>` instead of `Result<Html<String>, StatusCode>`. Use `file.contents()` (bytes) instead of `contents_utf8()`, and set `Content-Type` from the file extension via a small `match` (no new dependency needed — the served set is tiny: `main.js`, `index.html`, possibly a favicon):

- `.js` → `application/javascript`
- `.html` → `text/html; charset=utf-8`
- `.css` → `text/css; charset=utf-8`
- `.json` → `application/json`
- `.wasm` → `application/wasm`
- `.png` / `.svg` / `.ico` → their respective types
- fallback → `application/octet-stream`

Keep the `NOT_FOUND` behavior for missing/empty paths. `index_handler` (`game_server.rs:855`) already serves inline HTML correctly — leave it. The fallback route is registered at `game_server.rs:83`.

### Fix 2 — Correct the checkbox label

`frontend/index.html:473`:
```html
<label for="city-upgrades-enabled">Enable city upgrades</label>
<small class="hint">Supply (unit resupply &amp; attrition) is always active and cannot be disabled.</small>
```
Use existing hint/small styling if present in the page CSS; otherwise a plain `<small>` is fine. No backend change — the toggle correctly controls what it controls.

### Fix 3b — Fog vertex buffer / pipeline (position-only layout)

1. **`createFogPipeline()`** (lines 716-723): single vertex buffer entry — `{ arrayStride: 8, attributes: [{ format: 'float32x2', offset: 0, shaderLocation: 0 }] }`.
2. **WGSL `vert`** (lines 673-674): drop the `@location(1) uv: vec2<f32>` parameter and the `output.uv = uv;` assignment; keep only `@location(0) pos: vec2<f32>`. The `VertexOutput.uv` field can stay (unused by `frag`) or be removed — removing is cleaner.
3. **`updateFogQuad()`** (line 307): write exactly 8 floats = 32 bytes, matching the existing buffer allocation (no buffer resize needed):
   ```ts
   const fogPositions = new Float32Array([-1, -1,  1, -1,  -1, 1,  1, 1]);
   this.device.queue.writeBuffer(this.fogPositionsBuffer, 0, fogPositions);
   ```

Rejected alternative: stride 16 + UV at offset 8 + 64-byte buffer — wasteful, since the fragment shader discards the vertex UV.

## Notes / Risks

- `frontend/dist/` is baked into the binary **at Rust compile time** — a stale or empty `dist/` produces a silently broken frontend. **`make all` runs the frontend build but does not recompile the binary** — always run `make frontend-build && cargo build` (or `cargo run`) after any frontend change.
- `src/frontend/mod.rs:6` also declares a `FRONTEND` include_dir (dead code) — if it is ever wired into a route, it needs the same MIME fix.
- The fog fix is minimal (position-only). The vestigial UV attribute is removed rather than preserved for future use.
