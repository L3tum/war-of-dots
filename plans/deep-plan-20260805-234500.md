# Deep Plan: War of Dots — 8-Issue Quality Pass

Pipeline: REFINE → RESEARCH → COMPOSE (sequential subagents, driver-verified). Status: ready for review.

## Problem Statement

The game has 8 interconnected visual, protocol, and UX issues that degrade gameplay, plus a map-rendering pass:
1. All units/cities render red (wrong owner colors) due to UUID-prefixed player IDs
2. Borders use a 2-color toggle instead of per-player colors and only show one owner per edge
3. "Borders run from city to city" — symptom of (1) + (2)
4. Unit symbols render washed-out (no alpha blending on symbol/line pipelines)
5. Client has no `own_player_id` — cannot center camera on own territory or show own-side outlines
6. Camera always centers on map center, even for playing clients
7. Debug stats endpoint returns hardcoded zeros
8. Canvas lacks pointer capture + touch-action CSS (mobile/touch usability)
9. **Map/terrain looks flat and "abysmal"** — each cell is a single flat color (Plains `#7eb547`, Hills `#a0a04a`, Forest `#2d7a2d`, Water `#3878c9`, Mountain `#555`) with no variation, no shading, no shoreline, and hard grid seams between identical adjacent cells.

## Design

### Issue 9: Map/terrain rendering do-over

**Root cause:** `marchingSquares` (`frontend/src/game/terrain.ts`) emits one flat solid-color quad per cell. Identical neighboring cells form a uniform, lifeless wash with hard grid seams; water has no shoreline and mountains no shading.

**Approach (deterministic per-cell variation — no textures, fits the existing quad pipeline):**
- Add a deterministic hash of the grid coords `(x,y)` (e.g. a small integer-hash / `Math.sin` trick) to jitter each cell's color within a per-type luminance range, so neighboring same-type cells differ slightly instead of being an unbroken flat field.
- Give each terrain type a small **palette** (base + min/max shade) in `config.ts`, e.g. `TERRAIN_PALETTES`, so variation stays on-type.
- Add cheap **type-transition accents** so the map reads clearly:
  - **Coastline:** when a water cell borders a land cell, emit a lighter shoreline tint on the water edge (and/or a darker sand-brown rim on the land edge).
  - **Mountain:** darker top/light bottom (simple north-facing light) so ranges look shaded rather than flat gray.
  - **Forest:** slightly darker interior + lighter speckle to suggest canopy texture.
- Optionally add a faint grid-free blend: reduce per-cell seams by overdrawing 1px of background color, or make transitions via the accent quads.

**Implementation shape:** keep `marchingSquares(grid, cellSize, camera, zoom, w, h)` emitting world-space quads, but compute each vertex color with the per-type palette + hash + adjacency accent. This stays 100% inside the existing `mainPipeline` (opaque) and the existing `terrainPositionsBuffer`/`terrainColorBuffer` pair — no new pipeline or texture atlas required. Unit, city, border and fog layers (drawn above) are unaffected.

### Issue 1–2–5: Stable owner-to-index map + player identity

**Root cause:** Player IDs in real games are `"player_a3f2b1c0"` (UUID). `parseInt("a3f2b1c0")` → `NaN`. No `own_player_id` sent to client.

**Approach:** Add `player_id: String` to `PlayerState`. Server injects each connection's own ID into both FullState and every delta. Client builds a stable `ownerIdToIndex` map from the `LobbyPlayer` list it already receives (slot insertion order). Uses this map for:
- Unit dot colors → `PLAYER_COLORS[ownerToIndex[unit.owner] ?? 0]`
- City dot colors → `CITY_COLORS[ownerToIndex[city.owner] ?? 0]`
- Border colors → `PLAYER_COLORS[ownerIndex]` (each edge gets both owners' colors as dual quads)
- Camera centering → centroid of own units+cities when `ownPlayerId` is set
- Own-side outlines → semi-transparent halo behind own units/cities

**Why this over alternatives:**
- The client already has the player list from `LobbyUpdate`; reusing it avoids a new wire format.
- The `border_grid` uses slot indices (0..n) which correspond to lobby player order.

### Issue 2: Dual-colored borders

Each border edge separates two territories. We draw TWO thin quads offset by half the line width:
- Quad A: `PLAYER_COLORS[ownerA]` at offset `-halfWidth`
- Quad B: `PLAYER_COLORS[ownerB]` at offset `+halfWidth`

The border edge finder (adjacent-cell comparison) is already correct — do not rewrite it. We just store the **other owner** too: `BorderEdge { gridX, gridY, dir, ownerA, ownerB }`.

For a horizontal border at cell `(x,y)`→`(x+1,y)`: `ownerA=borderGrid[y][x]`, `ownerB=borderGrid[y][x+1]`; Quad A shifted UP, Quad B shifted DOWN.
For a vertical border at cell `(x,y)`→`(x,y+1)`: `ownerA=borderGrid[y][x]`, `ownerB=borderGrid[y+1][x]`; Quad A shifted LEFT, Quad B shifted RIGHT.

Each edge produces 8 vertices (2 quads) instead of 4. `BUFFER_SIZES.border` (1024*256 bytes) has ample headroom; `ensureBuffer` grows dynamically anyway.

### Issue 3: Symbol/line pipeline blend state

Add `blend` to the fragment target config of both `symbolPipeline` and `linePipeline` (matching fogPipeline's pattern):

```ts
targets: [{
  format: this.textureFormat,
  blend: {
    color: { operation: 'add', srcFactor: 'src-alpha', dstFactor: 'one-minus-src-alpha' },
    alpha: { operation: 'add', srcFactor: 'src-alpha', dstFactor: 'one-minus-src-alpha' },
  },
}]
```

### Issue 5: Own-side outlines

**Approach:** Reuse the pipeline structure. Before drawing unit/city dots, draw a larger semi-transparent quad behind each own-side entity using a new `outlinePipeline` (a blend-enabled variant of `mainPipeline` with `alpha 0.35`). Draw order:

1. Terrain (main, no blend)
2. Borders (line, with blend)
3. Path preview (line, with blend)
4. **Own-side outlines** (outline, with blend — BEFORE entities)
5. City dots (main)
6. Unit dots (main)
7. Unit bars (main)
8. Unit symbols (symbol, with blend)
9. Fog overlay (fog, additive blend)

Each outline quad is the entity quad expanded by `OUTLINE_EXPAND = 3.0` world units (independent of zoom).

### Issue 6: Camera centering

- **Playing client (has `ownPlayerId`):** Center on centroid of own units + cities, computed once on `applyFullState`.
- **Spectator/replay:** Center on map center (existing `centerCameraOnTerrain()`).

### Issue 7: Debug stats

Replace hardcoded zeros with real stats tracked per game in the tick loop (`tick_count`, `last_tick_ms`, `entity_count`). `debug_stats_handler` iterates active games and aggregates. In release builds it stays non-200 so the frontend hides the overlay; add a client-side toggle so it's still usable.

### Issue 8: Pointer capture + touch-action CSS

Add `touch-action: none` (and `user-select: none`) to the `#game-canvas` CSS. Switch `Controls` to the Pointer Events API (`pointerdown`/`pointermove`/`pointerup`), call `canvas.setPointerCapture(e.pointerId)` on right-button `pointerdown` and `releasePointerCapture` on `pointerup`/`pointercancel`. This prevents the browser gesture navigation triggered by right-click+drag.

## Implementation Steps

### Step 0: Map/terrain rendering do-over
**Files:** `frontend/src/game/terrain.ts`, `frontend/src/game/config.ts`, `frontend/src/game/terrain.test.ts`
- Add `TERRAIN_PALETTES` to `config.ts`: per type `{ base, min, max }` luminance range (keep `colorForType` as the base).
- Add a small deterministic hash `cellShade(x, y): number` (e.g. `(((x*374761393 + y*668265263) ^ (x*y)) >>> 0) / 2^32` or a `Math.sin`-based jitter) that returns a stable 0..1 value per cell.
- In `marchingSquares`, compute each quad's 4 vertex colors by lerping the type color from `min`→`max` by the hash (all 4 verts same per cell = flat but varied).
- Add **adjacency accents** read from `grid`: for each water cell with a land neighbor, lighten/warm the water edges (shoreline); for mountains, darken the top edge (light from south) for a shaded look; optionally add faint per-cell speckle for forest.
- Keep emission world-space quads in the existing `positions`/`colors` arrays so `renderer.ts` needs no pipeline change.

## Risks & Open Questions

| Risk | Mitigation |
|------|------------|
| Protocol change breaks existing clients | `player_id` new field; old client ignores unknown field, new client fallback to `""` when absent |
| Border vertex count doubles | Buffer has headroom + `ensureBuffer` grows dynamically |
| Outline GPU overhead | Only own entities (typically <20 quads) |
| `ownerIdToIndex` stale if lobby changes | Rebuild on every `LobbyUpdate` and on `FullState`; numeric-parse fallback for benchmark IDs |
| Camera jitter if units move | Center only on `applyFullState`, not every delta |
| Debug stats mutex contention | `try_lock`; debug-only |
| Double events on hybrid devices | Use unified Pointer Events API |

**Open questions:**
1. Per-player funds vs summed funds — out of scope; noted as follow-up.
2. `PLAYER_COLORS` currently 3 entries; consider expanding for larger games (wrap handles overflow).
3. Replay/spectator connections have empty `player_id` — correct (spectator view, map-center camera).
4. Exact schema-generation command (`generate_schema` bin / `npm run generate-types`) must be confirmed before Step 4.
