## 1. Context, Baseline, Acceptance Criteria

### 1.1 Architecture (verified in-tree this session)

Per tick (one tokio task per room, `src/server/game_server.rs`):
1. `game.tick_game()` (ECS; influence double-buffer publish).
2. Full snapshot: `game.unit_states_direct()` (`game.rs:1882-1893`, called `game_server.rs:559`) — materializes a fresh `Vec<UnitState>` for **all** units: `format!("unit_{eid}")` + String clones (owner/unit_type/symbol) + 2 equipment `Vec`s (per-item name Strings) + path `Vec`. Cities via `game.with_cities(...)` (`game_server.rs:562`).
3. Winner + active check: `game.determine_winner()` + O(players×units) scan (`game_server.rs:585-591`; `determine_winner` at `game.rs:1755-1780` runs a full `query::<(Entity,&UnitOwner)>()` **per player** + per-player city scan).
4. `run_network_phase` (`delta.rs:452`, called `game_server.rs:664-671` with `spliced=true`): `compute_shared_deltas` (`delta.rs:138`) — two `UnitStateDigest` builds + `HashMap` lookup per unit; emits `UnitUpdate` per changed unit (equipment `Vec` clone `delta.rs:212`, path clone `:242`); W8 count maps; per-player `build_delta_inner` (`delta.rs:333`); W9 splice encode (`SpliceShared`/`encode_delta_spliced` in `protocol.rs`).
5. Baseline commit: `prev_units`/`prev_cities` rebuilt as `HashMap<String,_>` by move (`delta.rs:552-559`) — 10k inserts + 10k key-String clones/tick.
6. Spectator block: union vision grid alloc + P×1 MB OR every tick while a spectator is connected (`game_server.rs:699-727`, `game.union_vision_grid_flat` `game.rs:1713`).
7. Send: outbox-by-move (`game_server.rs:735-753`) → `PlayerSender` (`room.rs:59-93`, **unbounded** `mpsc`) → WS bridge task in `handle_ws_game` (`game_server.rs:1472-1522`) locking `Arc<tokio::sync::Mutex<WsSink>>` **once per message**, one message per wake.

Wire: CBOR (ciboron 0.2), `GameDeltaMessage` (`protocol.rs:18-44`), `skip_serializing_if` Option fields on `UnitUpdate` + grid fields (W2; re-count the exact number at B0 before citing it in commit messages), flat 1-byte-per-cell grids sent **whole** when changed, f32 positions, `id: String` unit ids.

Churn root cause (verified): equipment wear = 1 item/tick per stocked slot (`supply.rs:274-280`); men refill at `recruitment_rate` (default **10**) **every tick** (`supply.rs:316-336`) — digest quantization (`delta.rs:39-57`) is calibrated to *drain* rate, not refill/wear rate → ~7,500–7,650 `unit_updates` on **every** tick.

### I2a — Recalibrate digest quantization to actual per-tick rates

**Problem.** `QUANT_MEN = 1.0` / `QUANT_ORG = 1.0` (`delta.rs:39-46`) and `equipment_count: u64` raw (`delta.rs:86-87`) cannot absorb the real per-tick change rates: men refill at `recruitment_rate` (default 10) every tick (`supply.rs:316-336`) and equipment wears 1/tick per stocked slot (`supply.rs:274-280`).

**Changes.**
1. `delta.rs`: `QUANT_MEN` becomes a **runtime step** passed into `UnitStateDigest::from_unit(u, men_step)`: `let men_step = game.settings().recruitment_rate.max(5.0);` (lobby `recruitment_rate` default 10, `protocol.rs` `LobbySettings`; `Game::settings()` already used at `game_server.rs:603`). `compute_shared_deltas` gains a `men_step: f32` parameter; `run_network_phase` reads it from `game`.
2. `equipment_count` digest: quantize to `QUANT_EQUIP: u64 = 5` (`(count / 5).round() * 5`; same for `max_equipment_count` — max is constant per unit, so it only matters at add; kept for symmetry).
3. `QUANT_ORG` stays 1.0; `QUANT_SUPPLY` stays 1.0 (W6).
4. Existing `digest_quantized_men_*` tests (`delta.rs` tests) are rewritten for the parameterized step (same same-bin/cross-bin value-pair structure, scaled ×10).

**Impact / acceptance (A/B vs B0 baseline):** `net_unit_updates` idle **≤ ~2,000** (from ~7,500 — kills the men-refill churn; wear churn remains, handled by I2b/I3); `net_wire_bytes` idle down proportionally.
**Files:** `src/server/delta.rs` (const, digest, `compute_shared_deltas` sig + callers, tests), `src/server/game_server.rs` (param at `:664` **and the replay-path caller at `:~1308`**), `src/benchmark.rs` (same call sites).
**Risks.** UI men-bar granularity becomes `max(5, recruitment_rate)` units (≤ 1% of a 1000-man unit — invisible); worst-case supply-stress drain ×10 (≈ 0.17/tick) still ≪ step. Mitigation: exact values still ride the wire when an update IS emitted (existing pattern).
**Commit:** one. **Deps:** none.

### I2b — Hot/cold field split in the shared update path

**Problem.** Every dirty unit emits *all* changed fields; wear/refill churn touches `equipment` + `men` every tick for ~7.5k units, cloning `Vec<EquipmentState>` (item-name Strings, `delta.rs:212`) and f32 fields that changed sub-visible amounts.

**Design.**
- **Hot fields (every tick):** `position`, `men`, `organisation`, `healing`, `resupply_enabled`, `encircled`, `attacking`, `on_water`, `embarking`, `disembarking`.
- **Cold fields (gated):** `equipment`, `path`, `supply_percent`, `boat_supply_percent`.
- Gate = `tick % COLD_EVERY == 0` **or** threshold crossing, with `COLD_EVERY: u64 = 10` and:
  - `equipment`: emit if `|Δequipment_count| ≥ 2 * QUANT_EQUIP` (i.e. ≥ 10 items) — per-tick wear (1/slot) never trips it; a combat casualty burst does.
  - `path`: emit if `(prev_len == 0) != (curr_len == 0)` or `|Δlen| > max(3, 10% * prev_len)` — captures "started moving" / "arrived".
  - `supply_percent` / `boat_supply_percent`: emit if a 10-point band is crossed (`(v / 10.0).floor() != (prev / 10.0).floor()`) — 1% steps within a band are absorbed by `QUANT_SUPPLY`'s existing silence.
- On a **cold tick** (every 10th): full digest including cold fields, exactly as today (catches everything the gate skipped).
- **Wire shape unchanged** — all 14 fields are already `Option` + `skip_serializing_if` (W2) and the frontend guards each (`frontend/src/net/connection.ts:385-455`, `replay/replay_player.ts:100-199`): an update simply carries fewer keys. Additive-safe, no version gate.

**Implementation.** `compute_shared_deltas` (`delta.rs:138`) gains `tick: u64` (callers: `game_server.rs:664`, `benchmark.rs`, replay path `game_server.rs:1308`). The update-building loop (`delta.rs:189-265`) checks the per-field gate before emitting a key; the digest-equality skip is extended so a non-cold tick treats cold fields as equal **unless** the threshold trips (compare cold fields conditionally against `prev`). The gate helpers (`cold_due`, `equip_threshold`, `path_threshold`, `band_crossed`) are small pure functions with unit tests — **I1 reuses the same helpers** in its per-field baseline compare (§2/I1), so define them in `delta.rs` now.

**Impact / acceptance:** `net_unit_updates` idle **≤ 1,000**; idle `net_wire_bytes` **≤ 600 KB** (I3 then cuts per-update bytes); equipment `Vec` clones (item-name Strings) drop to ≈ 0 on idle ticks.
**Files:** `src/server/delta.rs` only (+ tests), `game_server.rs`/`benchmark.rs` (tick param).
**Risks.** Equipment/path/supply UI lags ≤ 10 ticks unless a threshold trips — accepted (user-confirmed default "cold fields every ~10 ticks"). A unit wearing out fully between cold ticks shows stale bars for ≤ 1 s at 60 tps. Mitigation: the ≥10-item threshold and band crossing keep visible cliffs immediate.
**Commit:** one. **Deps:** I2a (step constants).

### I5 — Lazy winner / active determination (count-map driven)

**Problem.** Every tick: `determine_winner()` (`game.rs:1755-1780`) runs P archetype scans + P city scans, plus the O(P×N) string-compare active check (`game_server.rs:585-591`) ≈ 80k compares/tick — and the *result* is only used when `active_count ≤ 1`.

**Verified key fact.** `determine_winner`'s `players_with_power` set uses the **exact same predicate** as the active check (`unit_count > 0 || city_count > 0`); `total_funds/100` only affects the *sort*, not membership. Therefore:
- `active_count == 0` → Draw (existing branch, unchanged).
- `active_count == 1` → the winner **is** that sole active player; `determine_winner()` need not be called at all.
- `active_count > 1` → no game over; `determine_winner()` result unused.

**Changes.**
1. `delta.rs`: `count_by_owner` (`delta.rs:121`) is already generic — export it (`pub(crate) fn count_units_by_owner`). In `game_server.rs`, before the winner block (`:585`), build `let units_by_owner = count_units_by_owner(current_units.iter().map(|u| u.owner.as_str()));` (one O(N) pass, zero per-unit allocs — the W8 pattern) and a city-owner set in one O(cities) pass over `current_cities` (≤ 300).
2. Active check becomes O(P): `units_by_owner.get(pid).copied().unwrap_or(0) > 0 || city_owners.contains(pid)`.
3. Delete the per-tick `game.determine_winner()` call at `:585` and `winner_id_opt.unwrap_or_default()` at `:626` — the GameOver branch takes the sole-active pid directly (Draw branch: `"Draw"`). `determine_winner` remains, still used by the `human_count == 0` end-of-game path (`game_server.rs:~757`) **and the `players.is_empty()` path (`game_server.rs:792`)** — do not dead-code it.
4. `units_by_owner` is **passed into** `run_network_phase` (replacing the internal `current_units_by_owner` computation in `compute_shared_deltas`, `delta.rs:165`) — one map per tick instead of two; I1 then feeds the same map from incremental event accounting (§2/I1).

**Impact / acceptance:** 4 archetype scans + ~40–80k compares off the tick (research: ≈ 0.1–0.5 ms); zero wire change. A/B: `net_ms`/total tick ms flat-to-down; **no metric may regress > noise** (CPU-hygiene commit; the gate is "no regression").
**Files:** `src/server/game_server.rs` (`:585-643`, `:664`, **replay-path caller `:~1308`** for the `compute_shared_deltas` signature change), `src/server/delta.rs` (`compute_shared_deltas` sig, `run_network_phase`, `count_by_owner` export + tests), `src/benchmark.rs` (call sites).
**Risks.** Edge: LLM-only player with 0 units + 0 cities but funds — same as today (not "active", correct). Edge: city captured mid-tick after counts built — counts are built after `tick_game()` and deltas use the same snapshot, so winner/delta stay consistent (today's code already has this property). Manual gate: a 2-player game where one is eliminated fires GameOver for the *correct* winner (2-client check + replay viewer).
**Commit:** one. **Deps:** none (must land **before I1**, which removes the full `Vec<UnitState>` the active check currently scans).

### I1 — Entity-indexed baseline + incremental "diff-during-query" snapshot

**Problem (two):** (1) `unit_states_direct()` materializes all 10k units (Strings + 2 equipment Vecs + path Vec) **before** delta logic discards ~90% — dominates the 10 ms idle floor and most of the 89.6k allocs/tick; (2) the baseline commit rehashes a 10k-entry `HashMap` + clones 10k id Strings per tick (`delta.rs:552-559`). Entity ids are `unit_{eid}` with hecs slab ids (bounded, reused via free list) → an entity-indexed `Vec` is O(N), zero rehash, zero key allocs.

**Design.**
1. **Baseline structure** (`delta.rs`, replaces `NetworkBaselines::prev_units`):
   ```rust
   pub(crate) struct UnitSlot {
       pub entity: hecs::Entity,   // id + generation — respawn detection
       pub unit: UnitState,        // materialized exactly once per recruit
   }
   // NetworkBaselines::prev_units: Vec<Option<UnitSlot>>  (Option = tombstone)
   ```
   Vec indexed by `entity.id()`; grows to the high-water id (≤ total spawns; ~10k–50k for 10k-unit games — one-time amortized). `prev_cities` **stays a HashMap** (≤ 300 cities, keyed by string id elsewhere — documented non-goal).
2. **New snapshot** — `Game::unit_diff(&self, baselines: &mut Vec<Option<UnitSlot>>) -> UnitDiff` (`game.rs`, next to `unit_states_direct` `:1882`):
   - Single `world.query` with the same 9 components as `unit_states_direct`.
   - Per entity `e` (`idx = e.id()`): grow vec if needed; match `baselines[idx]`:
     - `None` → **added**: materialize full `UnitState` (Strings allocated **once, at recruit**), store slot, push to `diff.added`.
     - `Some(slot)` with `slot.entity != e` (hecs `Entity` PartialEq = id+gen) → **respawn in reused slot**: push old id to `diff.removed`, materialize + replace, push to `diff.added`.
     - `Some(slot)` same entity → **per-field compare in place**: numerics/bools by `!=`; path/equipment by count+slice compare; owner/unit_type/symbol by `str` compare. Cold fields are compared **only if I2b's gate says cold-due or threshold-crossed** (reuses I2b helpers — this is where I1+I2b compound: a wear-only tick never materializes).
     - Any field changed → mutate `slot.unit` fields in place (owner/unit_type/symbol re-cloned only if that String changed; `id` String is constant for the slot — zero copies; equipment/path `Vec`s rebuilt only when their values changed, reusing the old slot Vec via `std::mem::replace` where sizes match); compute `prev_digest` (pre-mutation, with I2a's `men_step`) and `curr_digest`; push `ChangedUnit { prev_digest, unit }` to `diff.updated`.
   - **Pass 2 (tombstones):** for each occupied slot, `world.is_alive(slot.entity)` (hecs `World::is_alive`); dead → push id to `diff.removed`, set slot `None`. (Pass 1's respawn branch already handled id reuse; pass 2 handles plain deaths.)
   - Returns `UnitDiff { added: Vec<UnitState>, removed: Vec<UnitState>, updated: Vec<ChangedUnit> }`. Wire `units_removed` ids = `removed` ids; `prev_units_by_owner` (W8) is maintained **incrementally** in `NetworkBaselines` (`+1` on add, `−1`/remove-on-zero on death; owner never changes mid-life) — no O(N) recount.
3. **`run_network_phase`** (`delta.rs:452`) takes `diff: UnitDiff` instead of `current_units: Vec<UnitState>`: `units_added = diff.added`; the `unit_updates` loop iterates `diff.updated` comparing `prev_digest` vs `curr_digest` (digest logic, including I2a/I2b gates, unchanged); baseline commit = **free** (baselines mutated in place during the diff). `SharedDeltas` keeps its `Arc` types.
4. **Callers:** `game_server.rs:559` (snapshot → `unit_diff`), I5's `units_by_owner` now read from `baselines` post-diff; `benchmark.rs` both call sites; replay path (`game_server.rs:1299-1317`) keeps `unit_states()`-based building (replay runs at 1× with few players — out of scope, documented).
5. **FullState** (`unit_states()`/`full_state_with_vision`) is untouched — joiners still get the full snapshot.

**Acceptance (A/B vs prior commit):** network-row allocs idle **≤ 15,000/tick** (from ~89.6k) and bytes **≤ 4 MB/tick**; idle `net_ms` **≤ 4 ms on non-grid-dirty idle ticks** (grid-dirty idle ticks are covered by I6/I4, which land later); biggest alloc **≤ 200 KB (no spectator, non-grid-dirty tick)** — the per-player final frame (`Vec::with_capacity(border + shared + vision + 256)`, `protocol.rs` `encode_delta_spliced`) is legitimately ≥ ~2 MB on grid-dirty ticks until I4, and I6 removes only the per-entry temps, not the final frame.
**Files:** `src/game/game.rs` (new `unit_diff`), `src/server/delta.rs` (baselines, `run_network_phase` sig + commit removal, ~10 test call sites), `src/server/game_server.rs`, `src/benchmark.rs`.
**Risks (medium).**
- *entity-id↔index invariant / id reuse* — mitigated by storing full `Entity` (id+gen) per slot and the two-pass removal; unit tests: recruit → death → recruit-at-reused-id (assert exactly one removed + one added, no ghost update), owner-never-changes invariant test.
- *digest computed pre-mutation* — pinned by the existing idle-skip/ownership tests run **unmodified in assertion** (`identical_snapshots_return_none`, `units_owned_change_is_detected`, `funds_only_change_is_sent_to_changed_player_only`, `two_players_share_read_only_baseline`) plus a new `diff_equals_full_snapshot_delta` test: `unit_diff` result vs a brute-force `unit_states_direct` pair-diff over a scripted recruit/move/wear/die sequence must produce identical added/removed/updated sets.
- *hecs `is_alive` availability in 0.11* — verify at implementation; fallback: `world.get::<&UnitOwner>(slot.entity).is_ok()`.
**Commit:** one. **Deps:** I2a, I2b, I5 (all must be in-tree).

### I6 — Zero-temp grid splice (kill the per-entry 1 MB `encode_entry` buffers)

**Problem.** `encode_entry` (`protocol.rs`, W9) allocates a fresh `Vec` per map entry: on grid ticks that is a 1 MB temp alloc **+** 1 MB copy for the vision grid **per player** and 1 MB for the shared border pre-encode — consistent with the 4.38 MB biggest-single-alloc.

**Changes.**
1. `protocol.rs`: new `encode_grid_entry(key: &'static str, grid: &[u8], buf: &mut Vec<u8>)` — writes `0x60|len`, key bytes, then a **hand-laid CBOR byte-string length prefix** (`0x40|n` for n<24; `0x59`+u16 BE; `0x5A`+u32 BE; `0x5B`+u64 BE — 1000×1000 grids need the `0x5A` branch) then `buf.extend_from_slice(grid)`. No intermediate Vec.
2. `encode_delta_spliced` (`protocol.rs`): vision entry uses `encode_grid_entry` when `vision_grid_diff` is present.
3. `SpliceShared::build`: border entry uses the same direct write into the shared buffer (the shared bytes become the final bytes themselves — no per-tick temp either).
4. Byte-for-byte invariant preserved: extend `splice_matches_encode_message_byte_for_byte` (`protocol.rs` tests) with a **70,000-byte** grid (exercises the `0x59` prefix) and a **1,000,000-byte** grid (exercises `0x5A`).

**Acceptance (A/B):** biggest single alloc **≤ 200 KB on non-grid ticks**; on grid-dirty ticks the final per-player frame alloc (≈ vision + border + updates, ≥ ~2 MB) is **unchanged by design** until I4 (I6 removes the per-entry `encode_entry` temps and their copies, not the final frame); grid-tick `net_ms` P90 down a few ms; alloc bytes on spike ticks −~5 MB (4× vision + 1× border temp+copy).
**Files:** `src/server/protocol.rs` only.
**Risks (low).** Hand-laid length prefix must match ciborium exactly — pinned by the extended byte-for-byte tests (0x48/0x59/0x5A branches, entry present and absent).
**Commit:** one. **Deps:** none; lands **before I4** (I4 shrinks grids — I6's win is largest while grids are still 1 MB, and I4's `Full` fallback reuses the same path).

### I8 — Lazy spectator union grid

**Problem.** While a spectator is connected, `game.union_vision_grid_flat(&all_pids)` allocates 1 MB + P×1 MB OR **every tick** (`game_server.rs:699-701`, `game.rs:1713-1731`), even when no player vision `Arc` changed.

**Design.** In the spectator block (`game_server.rs:688-727`) keep a tick-loop-scoped cache:
```rust
// next to `baselines`, in the tick-loop scope:
let mut spec_cache: Option<(HashMap<String, Arc<Vec<u8>>>, Arc<Vec<u8>>)> = None;
```
- Each tick: `sources = { pid → vision_grid_flat(pid).clone() }` (Arc refcount bumps only — `vision_grid_flat` returns `Option<Arc<Vec<u8>>>`, `game.rs:1570-1583`).
- If `spec_cache` exists with the **same pid set** and every `Arc::ptr_eq(stored, current)` → reuse the cached union `Arc` as `spec_vision` (no alloc, no OR; the spectator's vision diff then compares the identical `Arc` to its baseline → `None`, which is correct — nothing changed).
- Otherwise compute `union_vision_grid_flat`, wrap `Arc::new`, store.
- Same change in `benchmark.rs`'s `--bench-spectator` mirror path so the A/B sees it.
- Hygiene in the same commit: `let all_pids: Vec<String> = game.players().keys().cloned().collect()` at `:700` → reuse the I5-era borrowed pid list where lifetimes allow; otherwise keep (documented).

**Acceptance (A/B with `--bench-spectator`):** spectator-tick total-tick allocs −(1 MB alloc + ~5 MB mem traffic) on ticks where no vision changed (the common case; vision changes on ~29% of ticks at influence recompute); `net_wire_bytes` unchanged (the union is only *sent* when it differs from the spectator's baseline — behavior identical).
**Files:** `src/server/game_server.rs` (spectator block), `src/benchmark.rs`.
**Risks (low).** `Arc::ptr_eq` soundness: the influence double buffer publishes immutable `Arc`s and never mutates a published buffer in place (the W3 invariant, `influence.rs:66-68`) — the same invariant the vision diff already relies on. A stale-cache bug would freeze the spectator's fog → covered by extended spectator tests: one player's vision changes on tick N → union recomputed on N, cached N+1..N+2, recomputed when a second player changes.
**Commit:** one. **Deps:** none (independent of I1; lands before I4 so I4's diff construction is the only grid-logic change left in the spectator path).

### I3 — Compact unit updates (wire format commit #1)

**Problem.** A position+men+org update is ≈ 75 B+ on the wire: `id: String` (`"unit_1234"` ≈ 11–13 B CBOR text), f32×2 position (10 B), two f32 (10 B), and equipment updates carry full `Vec<EquipmentState>` with name Strings.

**Wire format (deliberate two-way protocol change; server+frontend ship together in one commit; fallbacks below keep old artifacts readable).**
1. **Numeric ids.** `UnitUpdate.id: String → u32` (the hecs eid; wire = CBOR uint, 1–3 B). `units_removed: Arc<Vec<String>> → Arc<Vec<u32>>`. **`UnitState` is unchanged** (`id: String` stays) — FullState and `units_added` (rare: recruits) keep string ids and full equipment; the only numeric/string duality is on the *update* path, exactly where bytes are paid P×/tick.
2. **Counts-only equipment.** `UnitUpdate.equipment: Option<Vec<EquipmentState>> → Option<Vec<u32>>` — per-slot **counts**, slot order = the unit's `max_equipment` order, which the client already holds (FullState / `units_added` deliver `max_equipment` with names + `cost_per_item`; names/`cost_per_item` are constant per unit type). No names on the wire ever again.
3. **Integer positions.** `UnitUpdate.position: Option<(f32,f32)> → Option<(u16,u16)>` (cell coords; maps ≤ 65535 — stress map is 1000; the code already indexes grids with `position.0 as usize`). `path: Option<Vec<(f32,f32)>> → Option<Vec<u32>>` packed `(y << 16) | x` (4 B/point vs 10–12).
4. `men`/`organisation`/`supply_percent`/`boat_supply_percent` stay f32 (CBOR float32, 5 B each — further narrowing not worth a compat risk).
5. **Resulting sizes:** typical hot update ≈ `id(3) + position(4) + men(5) + org(5)` + CBOR map overhead ≈ **20–25 B** (from ~75 B); a wear-tick equipment update ≈ `id(3) + 4·slots` (from ~60–100 B).

**Server changes.** `protocol.rs` (`UnitUpdate`, `GameDeltaMessage.units_removed`); `delta.rs` update builder (eid comes from I1's `ChangedUnit`, which carries the `Entity` — implement against that, no string parsing), `units_removed` map; `estimate_delta_size` (`protocol.rs:375-390`): re-tune the per-update constant (~200 → ~28) and **account for actual path length** (fixes the known under-hint → geometric buffer growth): `cap += updates.iter().map(|u| 28 + u.path.map_or(0, |p| p.len() * 6)).sum()`.

**Frontend changes (same commit).**
- `npm run generate-types` (schema: `id` → number, `units_removed` → number[], `equipment` → number[], `position` → [number,number], `path` → number[]).
- `frontend/src/net/connection.ts` `applyDelta` (`:385-455`):
  - `const uid = typeof update.id === 'number' ? update.id : Number(update.id.slice(5));` then `this.gameState.units.get(`unit_${uid}`)` — **Map keying unchanged** (string keys, renderer untouched).
  - `units_removed`: `for (const id of delta.units_removed) this.gameState.units.delete(typeof id === 'number' ? `unit_${id}` : id);`
  - `equipment`: `if (update.equipment) unit.equipment = unit.maxEquipment.map((m, i) => ({ ...m, count: update.equipment[i] ?? 0 }));`
  - `position`: unchanged code works (`[x, y]` tuple of numbers); `path`: unpack `p => [p & 0xffff, (p >>> 16) & 0xffff]` (unsigned `>>>` shift so high flat indices stay correct on large maps).
- **Replay compat (verified format facts):**
  - `/ws/replay` (main replay path): the server re-simulates the JSONL action log (`replays/{game_id}.jsonl` = *action* events + header only, `storage.rs:69`) and re-encodes deltas live through the same encoder → **always new format, zero work**; it exercises the same `applyDelta` (manual check required).
  - Legacy local JSONL mode (`?replay=file.jsonl`, `frontend/src/replay/replay_player.ts:100-199`): old files carry string ids, full equipment arrays, f32 paths → every field above gets a runtime `typeof` fallback exactly as sketched (string id → `slice(5)`; equipment array of objects → assign as-is; path points as arrays → use as-is).

**Acceptance (A/B):** per-update wire bytes ≈ −60–70% on any update-bearing tick; idle `net_wire_bytes` **≤ 300 KB** (compounds with I2b's ≤1k updates); `net_ms` down proportionally in the encode sub-phase (B0 counter); byte-for-byte splice test still green (the encoder is format-agnostic).
**Files:** `src/server/protocol.rs`, `src/server/delta.rs`, `frontend/src/net/connection.ts`, `frontend/src/replay/replay_player.ts`, `frontend/src/generated/protocol.ts` (regen), frontend tests.
**Risks (moderate).**
- Two-way protocol change — mitigated by: (a) `UnitState` untouched (FullState/join path byte-identical); (b) all fallbacks runtime-`typeof` (no version handshake; the CBOR clients are the same repo); (c) the server never deserializes `ServerMessage` in production (only protocol.rs tests + `console_client` generic decode).
- `u16` position overflow on >65535 maps — `debug_assert!(x < 65536)` at encode + a benchmark assertion that all unit positions are integral and in range (positions are grid cells; verified usage indexes arrays with `as usize`).
- Equipment slot-order mismatch (client `maxEquipment` vs server `equipment` order) — both come from the same `UnitEquipment` order (`game.rs:1916-1931`); unit test: an applied update preserves names.
**Commit:** one (server + frontend + regen together — a split would break `npm run typecheck` mid-sequence). **Deps:** I1 in-tree (eid availability); I2a/I2b strongly recommended (reduces what the compact format carries) but not required.

### I4 — Sparse grid diffs (wire format commit #2; prior plan's O10)

**Problem.** Any single-cell change ships the **entire** grid: 1000×1000 → 1 MB per vision diff (×4 players) + 1 MB border, on any dirty tick — up to ~5 MB vs KB-scale real changes (vision circles r5–r10 ≈ 300–1000 cells; borders shift by tens of cells).

**Wire format.**
```rust
#[derive(Serialize, Deserialize, JsonSchema, PartialEq)]
#[serde(tag = "t")]
pub enum GridDiff {
    #[serde(rename = "full")]   Full   { data: Vec<u8> },        // entire flat grid (1 B/cell) — same bytes as today
    #[serde(rename = "sparse")] Sparse { cells: Vec<u32> },      // each cell: (flat_idx << 8) | value
}
```
- `vision_grid_diff` / `border_grid_diff`: `Option<Arc<Vec<u8>>> → Option<GridDiff>`; `grid_width` unchanged (sent whenever either diff is present — sparse decoding needs the width: `y = idx / width`).
- Cell packing: `flat_idx` needs 24 bits (1000×1000 = 1M < 2^24 = 16.7M) + 8-bit value (vision 0/1; border player-idx 0..N or 255) = one `u32` per changed cell (4 B).
- **Threshold:** sparse iff `changed_count * 8 < grid_len` (≈12.5% — break-even vs `Full` is `changed * 4 == grid_len` = 25%, so 12.5% is byte-safe including CBOR array overhead; real changes are ≤ 0.1% of the map, i.e. always sparse). Named const `SPARSE_FACTOR: u32 = 8`, A/B-tunable.
- **Diff construction:** new helper `fn grid_diff(prev: Option<&[u8]>, curr: &Arc<Vec<u8>>, scratch: &mut Vec<u32>) -> Option<GridDiff>` (`delta.rs`) — reuse the existing `Arc::ptr_eq` fast-out (`delta.rs:127-133`, `:344-352`), else one O(cells) count+pack pass (~100 µs at 1 MB — acceptable, runs only on dirty ticks), else `Full` (Arc-shared as today — W3's `Arc` sharing carries into `Full { data }`; the shared border `GridDiff` is still built once and spliced P times via W9).

**Server changes.** `protocol.rs` (enum + `GameDeltaMessage` fields + `estimate_delta_size`: `Sparse` → `cells.len() * 6`, `Full` → `len`), `delta.rs` (border at `:127-133`, vision at `:344-352`, tests), splice path unchanged in shape (any `Serialize` value; byte-for-byte test extended). `NetworkBaselines::prev_vision`/`prev_border` **stay `Arc<Vec<u8>>`** (diff input; only the *wire* representation changes).

**Frontend changes (same commit).**
- `flatTo2D*` untouched; new `applyGridDiff(value, width, toBool)`: if `Array.isArray(value)` → old `Full`/legacy path; if `value.t === 'sparse'` → mutate the **existing** 2-D grid in place (`const i = c >>> 8; const v = c & 0xff; grid[i / width][i % width] = v !== 0` — unsigned `>>>` so flat_idx ≥ 2²³ stays correct on large maps) and mark dirty; else `Full { data }`. Existing grids are always present (FullState first) — documented precondition, guarded defensively.
- `frontend/src/net/connection.ts` (`:385-455`) and `replay/replay_player.ts` (`:125-129`): route both grid branches through `applyGridDiff`.
- **Replay compat:** identical structure to I3 — `/ws/replay` re-encodes live (zero work); legacy JSONL files carry plain arrays → the `Array.isArray` branch decodes them unchanged. New-format grid frames appear only in live/replay-WS traffic to the new frontend.

**Acceptance (A/B):** movement-tick `net_wire_bytes` **≤ 1.5 MB** (from 11.2 MB — ≥ 85%); grid-dirty idle-tick wire −~4–5 MB; `net_ms` P90/P99 (grid ticks) down several ms.
**Files:** `src/server/protocol.rs`, `src/server/delta.rs`, `src/server/game_server.rs` (spectator path uses `build_delta_inner`'s vision diff automatically), `frontend/src/net/connection.ts`, `frontend/src/replay/replay_player.ts`, `frontend/src/generated/protocol.ts` (regen).
**Risks (moderate).**
- Wire change in both directions — same mitigation family as I3 (co-shipped; runtime detection; legacy-JSONL fallback). Old client + new server breaks on grid ticks → **do not merge I4 without the frontend half** (single commit enforces this).
- Sparse applied before the client has any grid (join race) — FullState is always sent before deltas on connect (existing invariant, `game_server.rs:541-547`); defensive `if (!this.gameState.visionGrid) return;` + console warning in `applyGridDiff`.
- `Full` fallback when a recompute flips >12.5% of cells (massive simultaneous vision change) — byte-identical to today's behavior by construction; test: 30%-changed grid → `Full` chosen, bytes equal the legacy encoding.
**Commit:** one, **separate from I3** (per research; two independent wire-format reverts). **Deps:** I6 strongly recommended first (zero-temp path + byte-for-byte test already covers large byte-strings).

### I7 — Egress hardening: bounded, delta-only keep-latest

**Problem.** Egress is an unbounded `mpsc<Vec<u8>>` per connection (`room.rs:59-93`; WS bridge `game_server.rs:1479-1491`) with one sink lock per message and one message per wake: a stalled client ⇒ **unbounded memory** (invisible in the headless benchmark — the real-world "still bad" candidate), plus extra lock ops per tick per player.

**Message-classification rule (the invariant this commit protects).**
- **Delta class** — `ServerMessage::DeltaState` frames produced by the tick loop. Semantics: **keep-latest, droppable**. If tick N+1's delta exists, tick N's delta is worthless to the client (state is absolute, not cumulative) → the pending delta is *overwritten*, never queued.
- **Critical class** — everything else: `FullState`, `GameOver`, `Error`, `LobbyUpdate`, `Leaderboard`, `Advice`, `ClearSpectator`, `LlmReasonLog`. Semantics: **never dropped by the keep-latest mechanism** (each is a state transition the client cannot reconstruct from a newer delta). They flow in order; the *only* drop path is a last-resort overflow (below).

**Design.**
1. New `src/server/egress.rs`:
   ```rust
   #[derive(Clone)]
   pub struct EgressSender {
       critical: mpsc::Sender<Vec<u8>>,        // bounded 256
       delta: watch::Sender<Vec<u8>>,          // latest-wins, non-blocking
       alive: Arc<AtomicBool>,
   }
   pub struct EgressTask { /* owns both receivers + the WsSink */ }
   ```
2. `PlayerSender::Tcp` (`room.rs:59`) holds `EgressSender` (Clone = channel clone, same shape as today's `UnboundedSender` clone used by lobby relays at `game_server.rs:1577-1592`). The dead `Websocket` closure variant is untouched.
3. **`handle_ws_game` (`game_server.rs:1472-1522`):** the bridge task becomes `EgressTask::run(sink, critical_rx, delta_rx, alive)`. **Watch-channel contract:** the `watch` channel is initialized with an empty `Vec<u8>` and its receiver is created at channel construction (inside `EgressTask::new`, before any tick can send), so `changed()` can never miss the first delta (the empty initial value is never sent — `changed()` stays false until the first `send_replace`). On a delta wake: `while delta_rx.has_changed() { v = delta_rx.borrow_and_update().clone(); }` — only the last value is sent.
   - the `WsSink` **moves into the task** — the `Arc<tokio::sync::Mutex<WsSink>>` is deleted entirely;
   - `tokio::select!` (biased: critical first): on a critical wake, **drain** `while let Ok(m) = critical_rx.try_recv() { sink.send(...) }`; on `delta_rx.changed()`, take the latest value and send it;
   - sink error → `alive.store(false)`, task exits (dropping the critical receiver).
4. **Send-side semantics (tick loop, `game_server.rs:735-753`):**
   - Delta: `tx.send_delta(bytes)` = `watch::send_replace` (non-blocking, always `Ok`). The `is_ok()` liveness check on this path is replaced by `!tx.is_alive() → drop player` (checked in the send loop) — the channel-closed critical-send failure stays as a second liveness signal.
   - Critical: `tx.send_critical(bytes).await`; on `Err(Full)` → `while try_recv().await.ok() {}` drop-oldest + `try_send` + `tracing::error!` (a client stalling 256 *rare* critical messages is hard-stuck; dropping the oldest with a log is the committed policy — GameOver is the last message before the loop `break`s, i.e. the newest, and is protected).
   - `handle_tcp_client` gets the same treatment (it bridges identically).
5. **Spectator/liveness note:** spectators idle-skip (W5) so they rarely generate critical traffic; the keep-latest delta path is what protects memory under a stalled spectator.

**Acceptance (no headless A/B signal by construction — `TickData` doesn't model the bridge; verification is below):**
- Unit/soak test: sink that blocks on a `tokio::sync::Notify` (stalled client): send 500 deltas → pending memory bounded to ≤ 1 delta frame + drained criticals; after unblocking, the client receives exactly **the latest delta** (assert content = tick-500) and **all** critical messages in order.
- Liveness: sink errors at message 3 → `alive()` false → tick loop drops the player within ≤ 1 tick.
- Live-manual: throttled proxy (e.g. `tc` 200 kbit) on one of 3 WS clients — stalled client lags, other clients' delta latency **unchanged** (no shared lock — the `Arc<Mutex>` is gone), server RSS flat over 30 min (was unbounded).

**Files:** `src/server/egress.rs` (new), `src/server/room.rs` (`PlayerSender::Tcp` payload + `send`/`send_delta`/`send_critical`/`is_alive`), `src/server/game_server.rs` (`handle_ws_game`, `handle_tcp_client`, send-loop drop condition, lobby relay call sites), `src/benchmark.rs` (none — headless path bypasses `PlayerSender`).
**Risks (low–med).**
- *Liveness semantics change* (`is_ok()` → alive flag) — the W4 invariant "send failed → drop player" is preserved in outcome; the drop can lag by 1 tick (flag set by the bridge task) — acceptable, documented; test: dead socket drops exactly that player within ≤ 2 ticks, others unaffected.
- *Reorder* — a delta may be sent before an earlier tick's critical (select! fairness). Criticals are order-preserving *among themselves* (single FIFO channel); deltas are absolute state → any interleaving is safe. Documented.
- *`watch` value size* — the watch channel holds the last `Vec<u8>` (1–11 MB on grid ticks) per connection; that's the point (bounded, 1 frame) — assert in the soak test.
**Commit:** one. **Deps:** none (deliberately **last** in the sequence — see §3).
