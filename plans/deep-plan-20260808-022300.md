# Deep Plan: Decouple `supply` Cost from Population via Supply Coverage Grid

**Date:** 2026-08-08
**Target system:** `src/game/systems/supply.rs` (+ `src/game/components.rs`)
**Problem:** Supply does an O(N × Cₚ) sweep every tick — for each unit it loops all cities to find in-range ones, then does a random-access `world.get::<&UnitStats>` per unit. Population growth hits every term.
**Measured impact:** supply **4.62 ms** (report_18, ~100 units late-game) → **34.79 ms** (report_20_2, ~305 units).
**Goal:** Replace the O(N × Cₚ) per-unit city-distance loop with an O(1) per-cell grid lookup, and eliminate the per-unit random `world.get` with a contiguous ECS query.

---

## 1. Problem Analysis

### Current algorithm (supply.rs)
```
for player in ctx.units_by_player:
    find player's cities from ctx.cities  (linear scan ~20 cities)
    for each unit in player's units:
        cities_in_range = 0
        for each of player's cities:     // O(C_p) per unit
            check dist_sq < range_sq
            if in range: cities_in_range++
        rate = recruitment_rate + (cities_in_range - 1) * decay
        stats = world.get<UnitStats>(entity)  // random access, not contiguous
        if deficit + pool_ok: plan resupply
```

### Hot spots
| Cost source | Why expensive |
|---|---|
| O(N × Cₚ) distance loop | Every unit × every city = ~300 × 12 = 3,600 distance checks per tick |
| `world.get::<&UnitStats>(entity)` | Random-access ECS fetch per unit (cache miss per call) |
| `wb.funds.manpower.clone()` | Full HashMap<String,u32> clone per tick (12 players × 1550 ticks) |
| `player_city_indices` linear scan | O(all_cities) per player per tick |

### Key invariant
A unit's supply coverage only changes when:
1. The unit moves to a new tile
2. A city changes ownership or level (range changes)
3. A city is built/captured

→ We can **precompute a per-player supply coverage grid** each tick and look up coverage in O(1) per unit.

## 2. Design: Versioned Supply Coverage Grid

### New struct in `WorldBundle` (components.rs)
```rust
/// Per-player supply coverage grids — flat [y * width + x] layout.
/// Uses epoch-based invalidation (no need to clear/reallocate cells).
#[derive(Debug, Clone)]
pub struct SupplyGrids {
    /// Per-player grid: each cell stores (epoch, city_count)
    grids: HashMap<String, Vec<(u32, u32)>>,
    /// Global epoch — bumped every tick. A cell is valid iff cell.epoch == epoch.
    epoch: u32,
    /// Map dimensions (cached for rebuild)
    width: u32,
    height: u32,
}
```

**Memory:** `width × height × 8 bytes × num_players`. At 200×200×12 players ≈ **3.8 MB** (fits in L3).

### Rebuild algorithm (per tick)
```rust
fn rebuild_supply_grids(&mut self, wb: &WorldBundle) {
    self.epoch += 1;
    let cities = &wb.cities.cities;
    for city in cities {
        if let Some(pid) = &city.owner {
            let grid = self.grids.entry(pid.clone()).or_insert_with(||
                vec![(0, 0); (self.width * self.height) as usize]);
            let (cx, cy) = city.position;
            let r = city.supply_range as i32;
            // Stamp bounding box (disk approximation: stamp square, filter cells)
            for dy in -r..=r {
                for dx in -r..=r {
                    let (gx, gy) = (cx as i32 + dx, cy as i32 + dy);
                    if gx < 0 || gy < 0 || gx >= self.width as i32 || gy >= self.height as i32 {
                        continue;
                    }
                    let dist_sq = (dx as f32) * (dx as f32) + (dy as f32) * (dy as f32);
                    if dist_sq < city.supply_range * city.supply_range {
                        let idx = (gy * self.height as i32 + gx) as usize; // y*w+x
                        let cell = &mut grid[idx];
                        if cell.0 != self.epoch {
                            cell.0 = self.epoch;
                            cell.1 = 0;
                        }
                        cell.1 += 1;
                    }
                }
            }
        }
    }
}
```

**Complexity:** O(cities × range²) per tick. With ~12 cities × range=5 → ~80 cells/city ≈ **960 cell operations per tick** (independent of unit count).

### Supply run() rewrite outline
```rust

           recruitment_rate: f32) {
    let decay = wb.city_upgrades.settings.secondary_city_decay;

    // Step 0: rebuild grids (O(cities × range²), unit-independent)
    rebuild_supply_grids(world, world_entity);
```

### Key differences from current code
| Aspect | Old | New |
|---|---|---|
| City-distance loop | O(N × Cₚ) per tick | O(1) grid lookup per unit |
| Grid build | N/A | O(C × range²) per tick |
| ECS access pattern | Random `world.get` per unit | Contiguous `world.query` |
| Manpower snapshot | `HashMap<String,u32>` clone | Borrowed `HashMap<&str,u32>`, dropped before mutation |
| Per-player city scan | O(all_cities) per player | Eliminated (grids indexed by player) |

## 4. Behavioral Parity Guarantees

| Behavior | Preserved? | How |
|---|---|---|
| Multi-city rate formula `r + (n-1)·r·decay` keyed on COUNT | ✅ | Grid cell stores count, same formula applied |
| FCFS manpower gating (first unit served, later skipped if pool exhausted) | ✅ | Same contiguous query order = same unit ordering |
| "No owned city ⇒ no supply" | ✅ | Grid has no entry for player without cities → count = 0 |
| Equipment resupply (no-op today) | ✅ | Unchanged |
| `resupply_enabled` flag (cosmetic, not checked) | ✅ | Unchanged |
| City capture → supply coverage update | ✅ | Grid rebuilt every tick from current city ownership |
| City upgrade → range change | ✅ | Grid rebuilt every tick with current supply_range |

## 5. Risk Assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| Grid index bounds overflow | Low | Bounds checks in stamp loop, defensive index clamping |
| Epoch wrap (u32) | Extremely low | 4 billion ticks ≈ 100 years of continuous game |
| Memory spike (3.8 MB new) | Low | Allocated once per player, fits in L3 cache |
| Borrow conflict (immutable grid + mutable ECS) | Low | Two-phase: rebuild (mutable grid) → query (immutable grid) → write-back (no grid access) |
| FCFS order differs from old code | Low | Old code: `ctx.units_by_player` (HashMap iteration, non-deterministic). New: archetype query (deterministic). Both tested against parity, not exact ordering. |

## 6. Out of Scope (deferred to future phases)

- **Registrar / dirty-set:** true O(activity) tracking where only units that moved since last check are re-evaluated. This is the next step after proving the grid approach works.
- **Equipment resupply:** currently a no-op; not affected.
- **`resupply_enabled` flag:** currently cosmetic (not checked by any system); not affected.
- **Spatial chunking for other systems (influence, water, etc.):** similar grid pattern can be applied, but supply is the first proof-of-concept.
